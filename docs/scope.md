# Scope: what this repository publishes, and what it does not

This repository is a **partial release by design**. The boundary was drawn before anything was written, because a public repository for this particular paper sits in direct tension with two commitments the paper itself makes: that the audited stack is identified by structure and never by name, and that two artifacts in Appendix A are withheld.

Everything below follows from those two commitments.

## The three-way classification

| | Category | Contents | Rule |
|---|---|---|---|
| ① | **Published here** | the seven-item checklist, the six-step procedure, the verdict definitions, the numbers as transcribed from the manuscript, the scope and withheld-artifact records | free to read and reuse under the MIT license |
| ② | **Recorded, not published** | the two Appendix A artifacts: frozen scoring stack (`212717 B`, `2db0c9f622f79fb0`); branch structure and response surface (`12.2 KB`, `6f7449ec02af1f19`) | published by size and digest only; see [`withheld-artifacts.md`](withheld-artifacts.md) |
| ③ | **Never in this repository** | the audited stack's real name and its internal identifiers; raw workspace inputs, outputs and logs from the audited pipeline | excluded mechanically — see below |

> The identifiers themselves are **not written down anywhere in this repository**, including in the rules that exclude them. That is not an oversight in this table: a guard that names the thing it guards has published it. The list lives in an untracked local file, and `tools/check_no_leaks.py` reads it from there.

The distinction between ② and ③ matters. ② is material that exists and is deliberately held back; ③ is material whose presence here would break a commitment the paper makes in print. Withholding is disclosed; exclusion is enforced.

## Why ③ is enforced rather than assumed

A rule that lives only in a style guide is a rule that survives until the first hurried commit. Git makes this sharper than usual: a string that reaches a commit stays public even after a later commit removes it, because the earlier object remains in the pack. There is no clean undo.

So the exclusion is mechanical:

- **`.gitignore`** excludes by path — raw material, scratch scripts, build residue, and the two withheld-artifact name patterns (which leak nothing, since the manuscript already publishes them).
- **`tools/check_no_leaks.py`** excludes by **content**, which `.gitignore` cannot do, and by identifier-shaped **path**. It is intended to run before the commit rather than after it.

Two design points are worth stating plainly, because both were forced by the scan failing on its own first run:

1. **The identifier list is not in the repository.** An earlier draft wrote the token into `.gitignore` as a pattern — which publishes it just as surely as prose would. The list now lives in an untracked `.leaks.local`, and the scanner reads it from there.
2. **The scanner fails closed.** With `.leaks.local` missing it exits 2 and says the scan did not run, rather than reporting a clean tree. An unconfigured scanner that prints "PASS" manufactures the confidence it was built to provide.

The trade this makes is real and is written down rather than glossed: a `.gitignore` pattern fires on every `git add` with no dependency on anyone running a tool, and that is given up here. `.gitignore` section 2 carries the reasoning.

The scanner also carries `--self-test`, which plants a violation in a temporary copy and asserts the scan catches it. A scanner that cannot fail is decoration; the flag exists so that claim is checkable rather than asserted.

## What is deliberately not published, beyond ② and ③

**The code that produced the numbers.** The figures in the README are transcribed from the manuscript, not generated by anything in this repository. They are labelled as such. Releasing them as if they were reproducible output of this tree would be a worse error than not releasing the code.

**The environment pinning** that would let a third party re-run the audited stack. Without it, a released script would suggest a reproducibility that is not actually available.

## Standing limits on the claims

These are restated here because a repository is more likely to be read than a manuscript's §1, and because they bound what a reader may infer from anything above.

1. **TRIAD is an audit procedure, not a detector.** It does not grade a defence, rank it, or compare it against another defence. The manuscript contains no "superior to X" claim, and none should be read into material here.
2. **The layers compose by cancellation, not aggregation.** A clean reading at one layer does not offset a finding at another, and the three are not summed into a score.
3. **The audit is first-party.** It was designed and executed by the authors of the audited stack, read-only against artifacts frozen before the audit began. It does not satisfy the independence condition that the auditing framework cited in the manuscript's §2 treats as load-bearing.
4. **No second party has reproduced any number in this work.** Nothing in this repository changes that.
5. **One reference remains unconfirmed.** The manuscript's external reference verification confirmed 36 of 37 entries from first-hand publisher records; one entry (`Messick, "Validity"`, 1989) is recorded as unconfirmed, with the bibliographic details of the volume confirmed and only the chapter page range unresolved. It is neither deleted nor asserted.

## If you are reusing the checklist

The checklist is the part intended to travel. It is written to be run on a pipeline other than the one audited, and the seven prescriptions are the reusable content: each names a dimension to add, not a caveat to remember.

If you run it, the useful negative result is the one the manuscript reports — a check that **could not have failed** on the dimension that moved. That is the `blind` verdict, and it is where the procedure earns its keep.
